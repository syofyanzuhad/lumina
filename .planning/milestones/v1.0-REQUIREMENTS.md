# Requirements: Lumina

**Defined:** 2026-07-26
**Core Value:** Developers on Laravel stacks get Plausible-class analytics without leaving the Laravel ecosystem or adding new runtimes.

## v1 Requirements

### Site Management

- [x] **SITE-01**: User can register a new site with a domain name
- [x] **SITE-02**: User receives a unique tracking snippet (script tag) after registering a site
- [x] **SITE-03**: User can view a list of all their registered sites
- [x] **SITE-04**: User can switch between sites in the dashboard
- [x] **SITE-05**: Ingest endpoint rejects events for domains not registered in the `sites` table

### Tracking Script

- [x] **SCRIPT-01**: Tracking script is vanilla JS with no external dependencies
- [x] **SCRIPT-02**: Script bundle is < 2KB minified and gzipped
- [x] **SCRIPT-03**: Script sends: page URL, referrer, screen width, timestamp — no cookies, no fingerprint
- [x] **SCRIPT-04**: Script is async and non-blocking (does not impact host site performance)
- [x] **SCRIPT-05**: Optional custom events API: `window.lumina('event_name', {props})`

### Event Ingest

- [x] **INGEST-01**: `POST /api/collect` is a public endpoint (no auth required)
- [x] **INGEST-02**: Endpoint validates payload and rejects invalid or unregistered-site requests
- [x] **INGEST-03**: Validated events are dispatched to an `InsertEvent` queue job (not inserted synchronously)
- [x] **INGEST-04**: Endpoint responds fast regardless of DB write latency (queue decouples response from insert)
- [x] **INGEST-05**: Rate limiting applied per IP and per site

### Privacy & Visitor Uniqueness

- [x] **PRIV-01**: No raw IP addresses are stored in the database
- [x] **PRIV-02**: Visitor uniqueness uses a daily hash: `hash(IP + UserAgent + daily_salt)`
- [x] **PRIV-03**: Daily salt rotates every 24 hours (stored in cache/config, not per-visitor)
- [x] **PRIV-04**: Visitor hash is not reversible to an individual

### Dashboard

- [x] **DASH-01**: Dashboard shows total pageviews for selected date range
- [x] **DASH-02**: Dashboard shows unique visitor count for selected date range
- [x] **DASH-03**: Dashboard shows top pages ranked by pageview count
- [x] **DASH-04**: Dashboard shows top referrers ranked by visit count
- [x] **DASH-05**: Dashboard shows a daily pageview chart for the last 30 days
- [x] **DASH-06**: Dashboard data is accurate — matches manual SQL counts for the same date range
- [x] **DASH-07**: Aggregation queries use Laravel cache with a short TTL (≤ 60 seconds) to reduce DB load

### Date Filtering

- [x] **DATE-01**: User can filter dashboard to last 7 days
- [x] **DATE-02**: User can filter dashboard to last 30 days
- [x] **DATE-03**: User can select a custom date range

### Data Model & Compatibility

- [x] **DATA-01**: `sites` table: `id, domain, owner_id, created_at`
- [x] **DATA-02**: `events` table: `id, site_id, path, referrer, visitor_hash, device_type, country, created_at`
- [x] **DATA-03**: All migrations and Eloquent queries are compatible with both PostgreSQL and MySQL (no DB-specific raw SQL)
- [x] **DATA-04**: Device type is derived from screen width bucket (mobile / tablet / desktop), not stored raw

### Queue & Workers

- [x] **QUEUE-01**: Queue uses the database driver in v1 (no Redis dependency)
- [x] **QUEUE-02**: Queue worker runs as a persistent process on Laravel Cloud (not serverless invocation)

## v2 Requirements

### Analytics Depth

- **V2-01**: Custom event tracking dashboard UI (currently tracked but not surfaced in the dashboard)
- **V2-02**: Data export (CSV or JSON) for a selected date range
- **V2-03**: Public / shareable dashboard link (read-only, no auth required)
- **V2-04**: Goal / conversion tracking

### Scale & Performance

- **V2-05**: Postgres table partitioning per month (if events table becomes a bottleneck)
- **V2-06**: Consider ClickHouse/Timescale migration if Postgres aggregate queries degrade at real scale

### Collaboration

- **V2-07**: Team support — migrate `owner_id` → `team_id`, add per-team routing `/{team}/...`

## Out of Scope

| Feature | Reason |
|---------|--------|
| Real-time live dashboard (WebSocket/Reverb) | v1 polling/manual refresh sufficient; websockets add complexity before scale is proven |
| Multi-tenant SaaS billing | v1 is single-owner self-hosted |
| Teams in v1 | No validated need; `owner_id` model; refactor to `team_id` later if proven necessary |
| Mobile SDK | Outside basic analytics scope |
| Session replay | Outside basic analytics scope |
| Feature flags / A/B testing | Outside basic analytics scope |
| ClickHouse in v1 | Only if Postgres is a proven bottleneck under real load |
| MySQL-only optimizations | Postgres-first; MySQL via standard Eloquent only |
| OAuth / social login | Fortify email/password auth is sufficient for v1 |
